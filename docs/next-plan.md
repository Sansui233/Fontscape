## 2. 为什么要先做「共用基础」

现在所有预览都写 `fontFamily: "<css_font_family>"`，依赖字体**已安装且已启用**。下面三种情况都会让浏览器回退到别的字体，预览变成假的：

- 已禁用的字体（注册表条目被移除）；
- 自定义目录里没安装的字体；
- 以后的组合编辑器要按字符范围拼接不同字体。

所以第 0 项先做：后端按 font id 提供字体文件，前端用 `FontFace` 按需注册。第 2、3 项依赖它，第 4 项以后也会用到。

## 3. 建议顺序

```
1 缓存（启动性能，所有写操作都要更新它）
→ 0 按文件加载字体
→ 2 自定义目录（只读，不碰系统，风险低）
→ 3 安装 / 卸载 / 启用 / 禁用（写系统，风险最高；可以从字体库安装）
```

第 1 项与第 0 项互不依赖，可以对调。第 3 项拆成两步：先做当前用户（HKCU，不需要管理员），再做所有用户（HKLM，需要提权）。

## 4. 已确认的决策（2026-10-16）

| 问题 | 决定 |
| --- | --- |
| 系统级（HKLM）字体 | 第一版只读；提权 helper 放到第二步 |
| 卸载 | 与 Windows 自己卸载字体的做法一致：删除注册表条目（取消链接）并删除文件。文件进入系统回收站。确认框必须说明：**本应用无法撤销卸载**；从回收站还原文件也不会重新安装 |
| 安装方式 | 字体库目录里扫描到的字体：**原地注册**（注册表写完整路径，不复制）。拖进窗口的文件：**复制**到用户字体目录再注册 |
| 「已安装」的定义 | 注册表里有条目（已链接），文件可以在 Windows 字体目录里，也可以在任意位置（原地注册） |
| 同一字体既已安装又在字体库里 | 两份都显示：同属一个 family，详情页中各占一行，分别标出来源和状态，不去重 |
| 系统字体保护 | 文件属主是 TrustedInstaller 视为 Windows 自带；名单作兜底（未提出异议，按建议执行） |
| 组合编辑器 | 含义以后再讨论，本阶段不做 |

## 5. 不在本阶段

- 生成合并后的物理字体文件（涉及授权，也很少需要）。
- 修改系统级字体回退（注册表 `FontLink\SystemLink`）。
- WOFF / WOFF2（ttf-parser 不解压 WOFF2；Windows 也不能安装 WOFF）。
- 云同步、标签导入导出。

## 6. 验收方式

后端每步跑 `cargo test`，前端跑 `npx tsc --noEmit`，界面由用户手动验证。写系统的操作（第 3 项）需要在虚拟机或备用账户上先试。每完成一项，更新 `feature-status.md`。
