## 2. 为什么要先做「共用基础」

现在所有预览都写 `fontFamily: "<css_font_family>"`，依赖字体**已安装且已启用**。下面三种情况都会让浏览器回退到别的字体，预览变成假的：

- 已禁用的字体（注册表条目被移除）；
- 自定义目录里没安装的字体；
- 组合编辑器里要按字符范围拼接不同字体。

所以第 0 项先做：后端按 font id 提供字体文件，前端用 `FontFace` 按需注册。第 2、3、4 项都依赖它。

## 3. 建议顺序

```
1 缓存（启动性能，所有写操作都要更新它）
→ 0 按文件加载字体
→ 2 自定义目录（只读，不碰系统，风险低）
→ 3 安装 / 卸载 / 启用 / 禁用（写系统，风险最高；可以从字体库安装）
→ 4 组合编辑器
```

第 1 项与第 0 项互不依赖，可以对调。第 3 项拆成两步：先做当前用户（HKCU，不需要管理员），再做所有用户（HKLM，需要提权）。

## 4. 开工前需要你决定

| 决策 | 选项 | 建议 |
| --- | --- | --- |
| 系统级（HKLM）字体 | a. 第一版只读 b. 第一版就做提权 helper | a，第二步再做 b |
| 卸载时的文件 | a. 移到回收站 b. 直接删除 | a |
| 安装方式 | a. 复制到用户字体目录 b. 原地注册路径 | a；字体库可另加「原地激活」 |
| 系统字体保护 | a. 名单 b. 文件属主是 TrustedInstaller 视为系统自带 | b，名单作兜底 |
| 组合编辑器的含义 | a. 中西文混排（按字符范围拼一个虚拟字体）b. 标题 / 正文搭配 c. 两者 | a 为主，b 作为模板之一 |
| 同一字体既在字体库又已安装 | a. 合并为一个 family，标出两个来源 b. 分开显示 | a |

## 5. 不在本阶段

- 生成合并后的物理字体文件（涉及授权，也很少需要）。
- 修改系统级字体回退（注册表 `FontLink\SystemLink`）。
- WOFF / WOFF2（ttf-parser 不解压 WOFF2；Windows 也不能安装 WOFF）。
- 云同步、标签导入导出。

## 6. 验收方式

后端每步跑 `cargo test`，前端跑 `npx tsc --noEmit`，界面由用户手动验证。写系统的操作（第 3 项）需要在虚拟机或备用账户上先试。每完成一项，更新 `feature-status.md`。
